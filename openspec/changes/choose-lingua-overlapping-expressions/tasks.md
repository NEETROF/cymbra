## 1. The core (crates/lingua-core)

- [x] 1.1 `analysis/function_words.rs`: `pub fn is_preposition(lemma: &str, studied: StudiedLanguage) -> bool`, from each language's prepositions table (English's prepositions and particles, Spanish's, French's `FR_PREPOSITIONS`), beside `is_function_word`. Tests: `à`, `de`, `jusque` are French prepositions and `du`, `des`, `le` are not; `a`, `de` Spanish ones; `off`, `in` English ones; each language reads its own table (design D2).
- [x] 1.2 `analysis/tokenize.rs`: `pub fn is_hyphen_join(gap: &str) -> bool` — the gap between two tokens is one hyphen (soft hyphens read as nowhere, as `is_hyphen` reads them) or a hyphen, a `t` and a hyphen (`-t-`, any case). Tests: `-`, `-‧`, `-t-`, `-T-` join; ` `, `--`, `, ` do not (D3, G1).
- [x] 1.3 `engine.rs` `gloss_phrase`: computes `hyphened` — token `i` joined to token `i - 1` by `is_hyphen_join` over the text between their spans — and hands it to `match_expressions` beside `shares_span` and `elided`. No `Token`, `PhraseToken`, `PhraseMatch` or JSON field changes.
- [x] 1.4 `engine.rs`: whether a French run meets its headword's hyphens — the name (or the key) read by `headword_reading` when it holds a hyphen, every place `i` the reading joins by `is_hyphen_join` joined on the page (`hyphened[start + i]`); a reading that does not line up meets. Asked only by 1.8's G1, for the expression that would take a word: the scan's own matching does not read hyphens (D3, G1).
- [x] 1.5 `engine.rs`: the scan's lookup of the longest run that is a key and meets its headword at a start becomes a helper of `match_expressions`, used by the scan as before and by 1.6.
- [x] 1.6 `engine.rs` `match_expressions`: a run that is a key and meets its headword, in any language, before it is taken — the helper's run starting on its last token; when that run holds more tokens than the run, or (French, Spanish) the last token is the first half of a written word whose second half follows the run (`shares_span[start + len]`), and the run is built on a verb (1.7), and neither guard holds (1.8), the run does not match at that length: the shorter runs are tried, else the scan moves to the next token. The checks run cheapest first (lookup, guards, readings). Its doc comment states the rule and names this change (D1, D4).
- [x] 1.7 `engine.rs`: whether a run is built on a verb — a token, the last included, with a reading (`Pack::readings(lemma, lowercased surface)`) whose part of speech is `VERB` or `AUX`, and no token before that one a preposition (`is_preposition`). A pack without grammar reads no verb (D2).
- [x] 1.8 `engine.rs`: the three guards of D3 — the run keeps its last token when the expression that would take it does not meet its headword's hyphens (French; G1, 1.4), when that token is a preposition and the selection's next token reads `que` (French, Spanish; G2), or when the run the scan would take next after the run (from its end, covered articles included) ends past the end of the expression that would take the token and holds a token that is not a function word (all three languages; G3).
- [x] 1.9 Host tests in `engine.rs`, one per scenario of the delta, on inline packs keyed and named as the builder keys and names them, with grammar readings (a helper joining `build_pack_with_names` and `build_pack_with_grammar_for`): the French, Spanish and English scenarios of both requirements. And: a pack without readings keeps today's matches; a run whose verb follows a preposition (`à partir de`, `a pesar de`) keeps its last word; « Est ce que tu viens ? » written without its hyphen still answers `est-ce que`, the hyphen read only in an overlap; an English split word (« I don't » with `i do`) and a Spanish settled chain (`spanish_spans_for`, `a_french_match_ending_on_the_a_of_au_or_aux_covers_its_article`) gloss as before.
