Wire it into the server + worker; it is consumable by any app/module. _(Crate created + wired into the server; the worker consumes it as a normal dependency — the same `build_flag_service` wiring is added there when the first worker-side gate lands.)_
- [x] 1.1 Migration (owned by the crate): `feature_flags` / `app_config` (key TEXT, **app** TEXT `all`/`music`/`live`/…, value_type, value, rollout_scope `global`/`staff_only`, sensitive BOOL, updated_by, updated_at, PRIMARY KEY (app, key)) + `feature_flag_changes` audit (key, app, old_value, new_value, actor, at). _(Table `flag_overrides` + `feature_flag_changes`; `flags_svc` role/schema added to `backend/db/init`.)_
- [x] 1.2 A **code registry** of declared keys: name, **app scope** (all|specific), type, default, rollout scope, fail-direction (safe state), sensitive flag, short doc. Absent key ⇒ code default; only declared keys are editable. Keys resolve per the caller's app (token `aud`).
- [x] 1.3 A flags/config **service** with an **OpenFeature-shaped** typed evaluation API (`bool/number/string/json(key, default, ctx)`, built in-house — not the OpenFeature SDK) and a two-tier cache: **L1** = an in-process snapshot of the whole flag/config set (hot-path reads, near-zero latency), refreshed atomically on a short TTL (~15 s safety net) or on invalidation; **L2** = **Redis pub/sub** as the invalidation bus (publish a coarse "flags changed" on edit → all server+worker instances refresh L1 within ms). Fail-safe: Redis down → L1 last snapshot + TTL-poll Postgres; Postgres down → code defaults (kill-switches safe).
- [x] 1.4 Scope resolution per identity (global vs staff-only → admin/moderator only).

## 4. App consumption

- [x] 4.1 A **shared Flutter package** holding the flag client: **one** `GetEffectiveFlags` fetch → cache a **snapshot**; per-key reads are local/synchronous. Fetch on **launch and resume** sending the known **version** (cheap "unchanged"); optional light foreground poll (~5–15 min) version-guarded. **Stale-while-revalidate**: atomic swap, keep last-good snapshot on failed refresh (never a gap). **Identity-scoped**: watch auth state → on sign-out clear to anonymous/defaults, on user switch drop the old snapshot and refetch for the new identity (never inherit). **Local persisted cache keyed by identity** (or cleared on sign-out) for a flicker-free cold start. Expose via a Riverpod provider (service seam, fake in tests). Reusable by music/live/future apps. _(`packages/cymbra_flags`: `flagsProvider` notifier + seams; wired into `apps/music` via `cymbraFlagOverrides()` + resume refresh in main.dart.)_
- [x] 4.1a `GetEffectiveFlags` supports an **unauthenticated** call returning the anonymous global (non-staff) set, so pre-account UI (#8) respects kill-switches; else defaults. _(Mounted behind `OptionalAuthInterceptor`; a null bearer / expired token yields the anonymous set, not an error.)_
- [x] 4.2 Feature entry points read the provider to show/hide; backend still enforces regardless; a gated action that a stale client still shows **fails gracefully** (localized "unavailable", no raw error). _(Read API in place — `ref.watch(flagsProvider).getBool(key)`; concrete entry-point gates land with each feature, mirroring backend enforcement. Graceful failure is the existing no-raw-errors-in-UI pattern.)_
